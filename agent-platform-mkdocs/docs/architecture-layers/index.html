Build up the agent platform

Follow the service from a deployed agent to secure tool access, then add discovery, evaluation and telemetry.

Basic service

  1. App team
  2. Reviewed GitOps
  3. KRO composition
  4. Agent in team namespace

The platform operates the shared controller and runtime. The team owns the agent configuration and where it fits into the workflow.

JWT and approved tools

  1. User or workflow
  2. Agent Gateway
  3. Agent runtime
  4. Approved MCP or API

The gateway validates the caller JWT for the named agent. Outbound access has its own identity and audience. The backend enforces tool and resource scope.

Entra workload identity

  1. Projected service-account assertion
  2. Entra token exchange
  3. Destination-scoped access token

Federation replaces a provisioned client credential on this path. The resulting Entra access token is still a JWT. Use a distinct caller and agent identity.

Central registry

  1. Discover approved agents, tools and skills
  2. Choose reviewed versions
  3. Bind approved access through GitOps

The registry records ownership, provenance and supported versions. Gateway and backend policies enforce runtime permissions.

Evaluation

  1. Candidate revision
  2. Golden cases and denied cases
  3. Evidence for promotion review

Evaluate answer quality, tool choice and safety against the exact agent and tool revisions. The evaluator produces evidence for the release decision.

Observability

  1. Gateway, runtime and tools
  2. OpenTelemetry and collectors
  3. LGTM and Grafana

Correlate requests, authorisation outcomes, tool calls, latency and usage. Keep sampled traces and evaluation results distinct.
