What this improves, and what it proves

Demonstrated

  • Configuration change joined to specific workload evidence.
  • A benign metadata change avoided the demo rule.
  • A bounded, cited native kagent explanation.
  • Read-only observer denied resource-changing permissions.
  • Reporting route restored and sensitive edge removed.
  • Existing CNI and Agent Gateway configuration unchanged.

Still unproven

  • AgentShield HTTP traffic ingestion for this fixture.
  • Blocked lateral movement or NetworkPolicy enforcement.
  • Automatic MCP ingestion and authenticated adapter access.
  • Autonomous remediation and workplace compatibility.
  • General detection accuracy beyond the owned rule and control.

The implementation detail that mattered

The build has a reviewed --detector-only patch against pinned upstream source. It starts the existing engine and finding sink without model workers, and rejects model-feature combinations. Native kagent performs the separate evidence review through its existing chat-completions gateway.

The initial shared worker had stale registration after reboot. Both initial inputs were unaccepted and the session persisted zero tasks. An owned dedicated worker pool completed the handoff; the shared pool was not restarted. Its stale registration remains a separate lab issue.

Patch startup tests passed against a dedicated test database. All ten packet boundary tests passed. The observer and database listen only on loopback, and raw evidence remains private on the executor.
