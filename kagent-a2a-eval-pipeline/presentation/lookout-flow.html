Lookout: MR security review

Updated 25 Nov 2026. Built and lab-tested on a mock GitLab, and once on a real GitLab sandbox merge request. Advisory only: the agent leaves one note, a person still reviews and merges. Incremental (delta-only) review is switched off.

The flow

GitLab
1

MR opened or updated

A merge_request_event pipeline starts. Draft and WIP titles are skipped; a switch turns it off per project.

GitLab CI
2

Lookout job fires

Sends a pointer only: project, mr_iid, head_sha. No code in the message. allow_failure: never blocks.

agentgateway
3

A2A call

Same call path and error handling as Assay. Allowlisted route, rate limit, timeout, unique context id.

kagent on cluster
4

Agent reviews

mr-security-review reads its previous note, picks a mode, reads the diff at that exact commit through a small GitLab tool server.

GitLab MR
5

One note, human reviews

The note is updated in place on re-runs. The job checks the agent's tool calls: "completed" is not "posted".

Review modes (incremental is off)

ModeWhenCost seen in the lab
up_to_dateThe note already covers this exact commit (a retried job)about 7k input tokens, nothing posted
fullAnything else: a new MR or a new commit. The new note replaces the old one completely14k to 60k; about 40k for a 970-line MR
incrementalSwitched off. In a lab run it dropped two earlier findings from the note (the note is overwritten in place). The agent has no delta tool.was about 25k, but unsafe

What the agent can and cannot do

The agent's seven tools

Read the MR, its diff (pinned to a commit), a file, a folder listing, a code search, and the previous noteallowed (read-only)
Create or update the one review noteallowed
Approve, merge, push, branch, write a file, deleteno such call exists in the tool server's code
Delta-only diffserved, but deliberately not given to the agent
The limit is in code, not in the prompt, and a test fails if a write call appears. A token with more rights would still not give the agent more tools.

Guard rails, each tested

  • Untrusted input. MR text and code are data. An injected instruction is reported, not followed (lab: no off-allowlist tool called).
  • Exact commit. Short shas are resolved to the full 40 characters. A moved head is refused, so an old run never overwrites a newer review.
  • One note. Marker and header written by the tool server; only its own user's note is updated, so a commenter can't hijack it.
  • Sanitised note. No images, raw HTML or @mentions.
  • Honest coverage. Empty, trimmed or too-large diffs are never counted as reviewed. generated_file is ignored on purpose: an MR can set it to hide code.
  • Project allowlist. Empty refuses everything.

What the reviewer sees (sample from the lab)

Security review (automated, advisory) reviewed commit 1b1b1b1…Review mode: fullnot a merge gate

HIGH svc_06.py pickle.loads(request.data): unsafe deserialization of request data.

HIGH svc_11.py SQL built with an f-string: injection. Fix: a parameterised query.

HIGH extra.py:1 hardcoded API token. Fix: read it from the environment or a secrets manager.

Not reviewed: runtime behaviour (nothing was executed), dependency vulnerabilities, anything the diff tool omitted. If the MR is too big, the first line says PARTIAL: Reviewed X of Y files.

Input tokens are the whole context re-sent on each step, so a big diff in context is paid for repeatedly. About 1,500 lines fit in one review. Beyond that: split the MR, or add scanners in CI (not built).

Proven, and not proven

Proven

  • Lab, kagent 1.0.0-alpha17, mock GitLab: first review, same-commit retry, a push, and an injection MR. demo/run-demo.sh lookout: 4 of 4 checks.
  • Real gitlab.com sandbox MR: note posted, then updated in place; cleaned up after.
  • 362 offline tests; bundle verifier green.

Not proven

  • A real CI runner, the agentgateway route, kagent 0.7.x, a work GitLab, a least-privilege token.
  • GitLab's real behaviour on huge diffs.
  • Independent review: the second reviewer was unavailable.
  • Real coverage of very large MRs (needs risk-ranked paging or scanners).

Found and fixed by testing it

  • A stale-commit run overwrote a good review: now refused.
  • kagent 1.x ignores v1alpha2 agents: added a v1alpha3 manifest.
  • The model mis-copied long commit ids and looped: clearer errors, short ids resolved to full, a retry cap.
  • It over-browsed tiny MRs (10 calls): capped at 6 lookups.
  • Big MRs silently lost files (no pagination; empty diffs counted as reviewed): fixed, with a PARTIAL line.
  • Incremental review dropped two findings: switched off.
  • A successful retry of a failed post was reported as "no note": each call is now judged by its own result.
  • Duplicated note header and a compare call sent a short sha: fixed.
