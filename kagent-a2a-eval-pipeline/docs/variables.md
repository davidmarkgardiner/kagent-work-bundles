# Variables: what changes at work and what stays the same

## Changes at work (fill in; use placeholders in anything committed)

| Placeholder | What | Lab value shape |
|---|---|---|
| `{{MODEL_CONFIG}}` | ModelConfig the agents and evaluators use | an OpenAI-compatible config through the gateway |
| `{{APPROVED_HARNESS}}` | kagent 1.x Harness | one with a worker pool and snapshot policy |
| `{{READ_ONLY_TOOLS}}` | RemoteMCPServer name | the read-only Kubernetes tool server |
| agent names | `sentinel-investigator`, `guard-agent`, `agent-health-agent`, and the evaluators `completion-evaluator*` | rename freely; keep each contract's `agent`, `evaluator.agent` and `evaluator.subAgent` in step |
| cluster, namespace names | the incident key `binding/cluster/namespace/kind/name/finding-type` | whatever the receiver uses |
| `{{AGW_HOST}}`, token | gateway base URL and eval caller token | CI variables, never in git |
| tool names in `allowedTools` | the real read-only tools | `aks-mcp` read tools, for example |
| `policyNamespace`, route name, JWT subject | the Guard's block proposals | from gateway config, via the identity map only |
| GitLab project, labels | `sentinel`, `guard`, `agent-health` | the owner-approved ones |
| budgets | `guard/rules.yaml`, `guard/loop-limits.yaml`, each case's `maxTokens` and `maxToolCalls` | set from observed baselines |
| `{{GITLAB_URL}}`, `{{LOOKOUT_ALLOWED_PROJECTS}}` | Lookout: the GitLab base URL and the projects its review tool may touch (exact paths or `group/*`; empty refuses everything) | `https://<host>` and the sandbox project first |
| `{{PLATFORM_PROJECT}}`, `{{RUNNER_IMAGE}}` | Lookout CI template: the project that holds it, and the runner image that contains `lookout_review.py` and `a2a_capture.py` | internal |
| `LOOKOUT_MAX_TOOL_CALLS` | Lookout: warn above this many tool calls in one review (default 20) | set from observed reviews |
| `KAGENT_API` | Demo: `1x` (default) or `0.9` (any kagent 0.x). Picks the Agent API (`agents.api.kagent.dev` or `agents.kagent.dev`) and the A2A protocol for every scene; on `0.9` also set `A2A_BASE` to `.../api/a2a/<namespace>` and deploy `demo/lab/v1alpha2/*.yaml` | `demo/demo.env` |
| `SENTINEL_MODELCONFIG`, `SENTINEL_HARNESS`, `READONLY_MCP_SERVER`, `PYTHON_IMAGE`, `SENTINEL_APP_NS` | Demo `sentinel` scene (kagent 1.x): the investigator's ModelConfig (a model that follows numbered steps and hands off to a sub-agent; GLM 4.6 passed on the lab), its Harness, the read-only tool server, a python image the cluster can pull, and the namespace for the broken whisky app. Empty `SENTINEL_MODELCONFIG` skips the scene | `demo/demo.env` |

## Stays the same (pinned, do not change without re-testing)

| Item | Why it must not drift |
|---|---|
| kagent, agentgateway and Substrate versions in `PREREQUISITES-AIRGAP.md` | The A2A path, request shape and where tool calls appear all differ between 0.7.x and 1.x |
| Contract schema `completion-contract/v1alpha1` and the verifier's checks | They are the gate |
| One evaluator per contract, generated by `render_evaluator.py` | The worker must never choose the rules it is judged by |
| The ordered-steps worker and Guard prompts | A looser prompt scored 0 of 3 live; the ordered steps scored 3 of 3 |
| `delivery.owner: downstream` | A worker never writes the ticket |
| Direct blocking only for definite offences (`autoApply.signals`), with a re-validated single-subject Deny, caps, kill switch, ledger and a human `release`; never-block list; fail-closed spend state | Safety rules enforced in code |
| Scoring weights and hard gates (`docs/scoring.md`) | The scorer is the repo's own and is reused unchanged |
| Lookout's tool server code: GET calls plus note create and update only; no approve, merge, push or delete | The agent's safety limit lives in this code, and a test fails if it changes |
| Lookout's agent tool list (seven tools, no `lookout_get_delta_diff`) and its prompt, identical in both kagent manifests | Incremental review is off until findings are structured; a test pins both |
