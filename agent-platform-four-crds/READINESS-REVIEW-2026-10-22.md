## Validation and retained failures

The self-contained portable verifier passes **250 offline tests in six groups**. The complete source OTel suite passes 143 tests, the hosted source suite passes 52, the separate newer native adapter passes 11, and shared helper smoke checks pass. Offline verification still reports `targetVerified: false`. Source snapshots are hash locked, and local Kustomize/render tests remain included.

A final live attempt failed only the strict answer phrase check: Markdown split `exit 212` into `exit **212**`. Its four tool results and telemetry were valid, but it was not treated as a passing acceptance. That receipt is retained. The prompt now explicitly requests the contiguous phrase; the subsequent fresh run passed with the original document checks unchanged.

The initial observer negative test exposed a readiness bug after a denied dependency read; the fix immediately removes the green MCP stage. The same-namespace network probe initially contradicted an isolation assumption; inspection found the preserved additive allow policy, and a separate cross-namespace probe confirmed the narrower boundary.

Earlier archive verification found that Python `ZipFile.extractall` drops executable modes. Use system `unzip` or an equivalent mode-preserving extractor. An earlier macOS timeout-test process cleanup intermittently raised PermissionError; later source and extracted checks passed, but that historical failure remains recorded and is not a reason to weaken the test.

The public-safety scan passes with three reviewed hash-locked exclusions: the scanner's own detection pattern, and two existing version labels that resemble the broad private-address regex. These exclusions contain no target endpoint or credential.
