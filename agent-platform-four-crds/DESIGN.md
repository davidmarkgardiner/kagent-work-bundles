# Design synthesis
Usage: package.py content --output DIR; package.py render --config FILE --output DIR; package.py bootstrap --config FILE --gitops-commit FULL_SHA --output DIR. All commands local, new output directories only.
Candidate A: self-contained exact source snapshot, narrow AKS renderer deriving pins through existing implementations, isolated offline verifier. Candidate B: documentation-only instructions and hand-edited overlays; no runtime code delta, but operator manually coordinates source scope/artifact origin/profile enum/generated Agent hash/Flux RBAC. Choose A: those values cross too many ownership boundaries for manual edits to be reliable.
Implementation boundary: optional origin/profile inputs preserve canonical defaults; no lab deployment. Source closure retained under implementation/platform/skills-registry and implementation/scripts. Lock every copied file. No lab Flux installer/server. Export only required fixtures plus historical receipts separately. Existing approved Flux/platform service account/ModelConfig/credential provisioning remain operator prerequisites. Private auth uses Secret references only.
Rendered tree: platform exact four CRDs/controllers/scoped roles; content pinned same-namespace source and two releases; hosted immutable request; golden skill-only scenario pinned to generated Agent. Bootstrap staged platform first, then content/hosted/golden. Platform reconciliation SA exists in Flux NS; request SAs in app NS; Flux impersonation subject uses Flux NS. Prune false for platform and releases; Hosted/scenario prune false as conservative rollback.
Work profile: explicit namespace/Flux namespace/KAgent namespace/exact source origin/controller image digest/model spec hash/approved native imageRegistry/asserted runtime image/scheduling. Native runtime arbitrary image/tag unsupported; target read-only compatibility remains required. Owner instructions task-directed so Golden only reads skill/catalog; manual Hosted acceptance asks for both sources.
No live target claims. Historical Proxmox receipts remain explicitly historical. New offline tests include isolated copy, lock validation, deterministic rendering, missing/unknown/unsafe config rejection, source/pin/RBAC/profile closure. Provider provenance: independent native design + parent documentation-only alternative; Claude usage-limited from preceding task and Grok unavailable, no replacement concealed.
