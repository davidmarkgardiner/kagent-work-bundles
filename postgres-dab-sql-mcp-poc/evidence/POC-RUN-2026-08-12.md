# PostgreSQL + pgvector MCP POC — live evidence

Date: 2026-08-12

## Verified current capability — bounded PostgreSQL route

The `red` HomeLab ran a disposable PostgreSQL 17 + pgvector `0.8.6` database
with only synthetic compliance findings. The database had an HNSW index named
`compliance_findings_embedding_hnsw`; a direct query returned `2` open
findings at severity rank 3 (high) or 4 (critical).

`postgres-compliance-readonly-mcp` discovered exactly:

```text
get_compliance_data_product_details
get_open_high_severity_compliance_findings
```

`postgres-compliance-lab-agent` was `Accepted=True, Ready=True`. A completed
A2A task called both tools with `isError:false` and returned:

```text
POSTGRES_MCP_REPLY_OK
Open high/critical compliance findings: 2
```

## Verified current capability — official DAB discovery only

Microsoft Data API Builder SQL MCP `2.0.9` successfully started against the
same PostgreSQL service and kagent discovered its configured read-only tool
surface. This does **not** count as data-query proof.

## Unknown / requires validation — DAB PostgreSQL execution

`read_records` failed at runtime with an Npgsql reader exception, and DAB
reported `aggregate_records` unsupported for PostgreSQL. The agent returned a
transparent failure rather than inventing a count. Treat DAB/PostgreSQL as
blocked pending a Microsoft-supported fix/version confirmation.

## Not proven

- Amazon RDS networking, TLS, authentication, IAM/Secrets Manager, logging,
  audit, backups, cost, performance, or data governance;
- any real compliance data or vector similarity query; and
- a production-ready custom adapter image.
