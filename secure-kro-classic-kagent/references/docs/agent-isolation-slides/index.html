SOURCE-BASED DESIGN DEMONSTRATION

Evidence, with boundaries.

What was recorded

A historical disposable AKS pilot recorded direct ServiceAccount federation, a direct child grant, and manual token refresh. That is the narrow pilot boundary.

What remains unverified

The full workplace caller-UAMI path, inherited grants, unattended refresh, and OBO are unverified. The OBO policy rejection is a design conclusion for the illustrated app-only policy, not a tested runtime result.

Deployment mechanics

OBO requires a separate client app, a signed-in user token addressed to the blueprint, T1 + Tc exchange, and the applicable admin consent and permission inheritance. A shared MCP ServiceAccount does not itself apply each human's Kubernetes RBAC; explicit downstream authorization is required.
