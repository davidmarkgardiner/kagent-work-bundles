01 / 07

The operating loop

Every handoff leaves a checkpoint.

The poller advances one parent issue by one stage per run. It checks GitLab artifacts before changing the board label.

01 · INPUT

Label issue

sdlc-rig-poc + agent:plan puts a sandbox issue on the board.

02 · PLAN

PM splits it

The PM reads criteria and creates one child issue. The poller verifies its identity.

03 · BUILD

Worker commits

PM delegates over A2A. The builder writes an agentic/ branch through scoped GitLab MCP.

04 · TEST

CI gates

GitLab CI must pass on the branch SHA. Tester checks the real pipeline and committed files.

05 · REVIEW

Draft MR + note

The PM opens a draft MR. Reviewer posts a PASS or CHANGES_REQUESTED note tied to the SHA.

06 · DECIDE

PM accepts

Only a green pipeline and matching PASS note can reach agent:accepted.

Failure path: failed CI or requested review changes returns to agent:changes → builder rework → new CI → new review. Old PASS notes cannot approve a new SHA.

Who talks to whom

PM delegates. GitLab remembers.

All agents ran on one control-plane VM and used Kimi through the existing agentgateway model route.

Durable inputGitLab issue board

Parent labels are the queue. Child issues, commits, pipelines, MRs, and notes are durable evidence.

Source of truth
Controller + coordinatorCronJob → PM agent

The two-minute poller calls the PM for one stage. The PM assigns builder, tester, or reviewer through kagent A2A.

One model turn per poll
Specialist workersBuilder · Tester · Reviewer
  • Builder commits allowed files.
  • Tester checks GitLab CI.
  • Reviewer records a verdict on the draft MR.
Issue labels→CronJob→PM + A2A workers→GitLab MCP + CI→Draft MR

The model calls use agentgateway. The GitLab MCP route remains direct in this pilot. The Kubernetes worker VMs stayed off; the host had 34 GiB available memory and no swap use at final check.

Walkthrough B · the repair loop

Issue #41 did not pass first time.

The test needed to prove a README smoke criterion was inside the Verification section. CI failures and reviewer findings sent it back through the board until that was true.

01 · CI failed

First build broke

Pipeline 2886848238 failed. The board labelled the parent agent:changes and sent the CI trace to the builder.

02 · Review found a gap

Phrase check too broad

A green run still searched beyond the Verification heading. Reviewer notes requested a bounded section assertion.

03 · Repair was gated

CI caught new errors

A missing node:test import and then a regex mistake failed CI. The poller retained the reviewer finding during rework.

04 · Timeout recovered

Commit beat the reply

PM A2A timed out after 150 seconds. GitLab already held a new commit, so the poller resumed from the verified SHA.

What the evidence says

Strong pilot proof. Clear limits.

The artifacts were checked independently from model replies. The deck is a dated walkthrough, not a live dashboard.

01

Real delegation

PM-to-specialist A2A calls invoked builder, tester, and reviewer. The PM did not simply describe work.

02

Verified artifacts

Each accepted parent had exactly one child, branch SHA, successful pipeline and test job, draft MR, and matching PASS note.

03

Recovery exercised

Failed CI routed to changes. A timed-out PM turn still advanced after its committed SHA was found in GitLab.

Ready for bounded sandbox work

What we can use now

  • One cluster, one model, one fixed sandbox project.
  • Two-minute labelled board polling.
  • Small, allowed-file tasks ending at a draft MR.
Still to prove

What this run did not establish

  • Fully unattended completion of several issues: most checkpoints were manually accelerated.
  • Concurrent manual and scheduled Jobs need a shared lease; suspend before manual runs today.
  • Cross-cluster assignment, four-model routing, and MCP gateway policy.
