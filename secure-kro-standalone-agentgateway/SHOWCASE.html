What the request creates

The runtime is a normal long-running Deployment using an existing approved Python helper image and immutable code/content ConfigMaps. No new custom-image build is required. It does not need Substrate, native worker pools, Harness, actors or the native CLI. Shared Gateway, authorization, verification and policy services are installed once as platform prerequisites.

The secured execution path

  1. The caller presents an audience-bound JWT to Agent Gateway. The generated HTTPRoute targets the exact front Service; a destination ReferenceGrant consents to that cross-namespace reference.
  2. The trusted facade performs TokenReview and checks current request identity, resource pins and approval. It gives the runtime a private, short-lived invocation handle.
  3. The runtime uses its projected worker JWT and handle through the Gateway for the approved model and typed MCP operation. It receives no provider key or API-audience credential.
  4. The independent verifier runs the documentation scenario, checks actual model/tool/content evidence and denial behavior, then publishes time-limited approval. Expiry, revocation or changed authority denies fresh work.

A ReferenceGrant supplies destination consent; caller authentication and authorization remain separate checks. Platform/KRO administrators and approved profile authors are trust roots.
