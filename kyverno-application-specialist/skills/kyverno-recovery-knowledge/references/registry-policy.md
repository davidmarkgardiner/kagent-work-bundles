# Approved registry fixture

The intended image pattern is `docker.io/library/*`. The synthetic faulty pattern
is `docker.io/libary/*`, which misspells the namespace and rejects the approved
`docker.io/library/busybox:1.36` image. An unapproved image from
`unapproved.example.invalid` must remain rejected after repair.

The policy is namespaced and matches labelled application Pods. Autogenerated
controller rules are disabled for this fixture. A Recreate rollout can therefore
delete the old Pod while the replacement Pod is rejected. Existing Pods are not
retroactively evicted by an admission-policy change.

Restore the intended pattern only after confirming this actual differing field
in current Kubernetes and GitLab evidence. Preserve Enforce, the selector,
namespace, and negative test. Deleting the policy, setting Audit, or disabling
webhooks does not repair the registry typo.

Kyverno versions may omit condition observedGeneration. Do not invent a native
status field. A separately labelled active-probe observation requires identical
policy UID, generation, and spec before and after the positive/negative probe
window, with the actual denial naming the selected policy and rule.

The GitLab CI tests the declared pattern and retained scope/enforcement.
Actual Kubernetes admission and application probes establish target behavior.
Flux Ready alone, an MR merge, or an old serving replica is insufficient.
