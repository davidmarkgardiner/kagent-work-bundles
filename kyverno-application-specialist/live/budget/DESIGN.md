# Native model budget proxy candidate

Types: `Config` is an immutable, validated run identity and upstream URL plus positive integer request/input/output ceilings. `BudgetStore` owns a SQLite configuration hash, aggregate counters and one minimal row per reserved attempt. A reservation is a monotonically allocated integer; terminal updates are conditional on its pending status. `Handler` validates bounded JSON and forwards through a fixed `HTTPConnection` or `HTTPSConnection` without redirects or retries.

Two alternatives were considered. Prompt-only limits preserve the direct gateway path but cannot enforce a shared total across agents, concurrency or process restart. A narrow HTTP proxy enforces the shared limit before contacting the existing approved gateway and preserves native SDK response semantics. The proxy is chosen.

Actual hard ceilings are 32 reserved requests, 524288 inbound body bytes per run, 65536 inbound body bytes per request, 1200 requested output tokens, a 1048576-byte upstream response and 100 seconds for the whole upstream operation. Config may lower the three run ceilings, never raise them. Malformed/rejected completion attempts consume a request reservation. Invalid framing and oversize bodies consume no bytes because they are not read. A permitted body reserves its declared bytes before reading; ambiguous partial-read failures do not refund those bytes. Once the remaining byte allowance cannot fit a declared body, that attempt is reserved with zero bytes and rejected without reading it. Requests after the request cap are rejected without a reservation. HTTP request framing requires one nonnegative Content-Length and no Transfer-Encoding.

An advisory file lease permits one serving process per database. SQLite uses BEGIN IMMEDIATE to reserve before body receipt and upstream I/O. It stores only sequence, input size, SHA-256 digest, terminal category, HTTP status and finite numeric upstream usage counters. It never stores request/response content or headers. On restart, pending records become interrupted, with no refund or retry. Existing database identity/hash mismatch fails startup. GET /healthz contains aggregate usage/status counters only.

Only model/messages/tools/tool_choice/temperature/max_tokens/stream/parallel_tool_calls/response_format/store are accepted. The model must equal configured model, stream must be false, max_tokens must be a positive integer within the configured ceiling. Missing model/max_tokens are filled from fixed config; missing stream defaults false. JSON NaN, duplicate keys, unknown fields and unsupported encodings are rejected. Tools and messages are forwarded without logging. Responses must be valid JSON objects; upstream errors keep their actual body/status. Invalid/oversized/ambiguous upstream results produce explicit proxy errors and retain the reservation. There is no fixture/provider fallback.

The upstream is HTTPS with normal certificate verification, or HTTP only for a configured Kubernetes service DNS name (.svc or .svc.cluster.local). URL authentication, queries, fragments, non-root paths and redirects are disallowed. Outbound headers are fixed Content-Type/Accept plus the original Authorization and syntactically valid W3C traceparent only. There are no generated spans. Host/port are runtime bind settings, not caller-selectable destinations.
