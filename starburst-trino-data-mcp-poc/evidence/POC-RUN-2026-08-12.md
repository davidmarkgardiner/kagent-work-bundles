# HomeLab Trino fallback MCP POC — 2026-08-12

## Scope and boundary

This is **option C** from the data-MCP decision plan: official open-source
Trino plus a purpose-built, read-only MCP adapter using synthetic data. It is
not a Starburst Enterprise or production-data proof.

Starburst Enterprise's native MCP path was not installed because its documented
Kubernetes deployment requires Starburst Harbor credentials, an SEP licence,
and an MCP-server licence. None was available in the HomeLab/public repo.

## Live verification result

The following command was run against the `red` HomeLab context:

    sh work-agent-bundles/starburst-trino-data-mcp-poc/scripts/verify.sh red

It returned exit `0` and the following markers:

    TRINO_SYNTHETIC_QUERY_OK [['high', 3, Decimal('9300.00')], ['low', 12, Decimal('2400.00')], ['medium', 7, Decimal('6100.00')]]
    REMOTE_MCP_DISCOVERY_OK
    KAGENT_AGENT_READY_OK
    VERIFY_PASS

The live discovery record showed exactly these tools:

    search_data_products
    get_data_product_details
    get_overdue_risk_summary

The `trino-data-product-lab-agent` was `Accepted=True, Ready=True`; its explicit
mount contained those three names only. No arbitrary-SQL or write tool is
implemented by the adapter.

## Conversational A2A acceptance result

After the baseline verifier, a separate live A2A request explicitly instructed
the Agent to call `get_overdue_risk_summary` and return the aggregate. The
controller returned HTTP 200 with task ID
`bd953892-e236-4d35-8691-7dd3093c230b`, terminal state `completed`, a tool
response with `isError:false`, and the final text:

    DATA_MCP_REPLY_OK, high: 3, low: 12, medium: 7

The public-safe, trimmed controller receipt is committed as
[`A2A-CONVERSATIONAL-RECEIPT-2026-08-12.json`](A2A-CONVERSATIONAL-RECEIPT-2026-08-12.json).
It contains the request, task/context IDs, the bounded tool name, its synthetic
response, the final text, and terminal state; it deliberately omits model
reasoning and any non-essential controller metadata.

## Repeatable full verifier rerun

The bundle was then redeployed from its checked-in manifests and the full
verifier was rerun against `red`. It exited `0` with these additional markers:

    TRINO_SEED_JOB_COMPLETED_OK
    A2A_TOOL_CALL_OK
    A2A_CONVERSATIONAL_RESPONSE_OK
    VERIFY_PASS

This rerun proves the checked-in `deploy.sh` and `verify.sh` work together:
the disposable seed Job is recreated, the synthetic table is queried directly,
and kagent completes a conversational A2A request using the bounded MCP tool.
The A2A verifier checks the stable result contract—not prose formatting:
`DATA_MCP_REPLY_OK` plus high/medium/low account counts `3`, `7`, and `12`.
It still does **not** turn this option-C fallback into proof of the official
Starburst native MCP or Microsoft DAB SQL MCP paths.

## Runtime observations

- `trino-coordinator`, `trino-worker`, and `trino-readonly-mcp` were all
  Running/ready in the disposable `data-mcp-poc` namespace.
- The adapter had `automountServiceAccountToken: false` and only synthetic
  in-memory values from the seed Job.
- Agent logs prove a Streamable HTTP MCP session was negotiated with the
  adapter and show multiple successful MCP HTTP calls. The agent also received
  successful model-gateway HTTP responses.
- An earlier retry returned no artifact text. The helper previously extracted
  only `result.artifacts[].parts[].text`, so it could not recover a terminal
  assistant message held solely in task history. The helper now supports an
  explicit raw receipt and a final-agent-history fallback; the separate
  acceptance request above returned the normal artifact projection as well.

## Defects corrected during the run

1. Trino's 1 GiB heap initially conflicted with its default 1 GiB per-node
   query memory. The values now set 512 MiB query memory and 256 MiB headroom.
2. The POC adapter installs pinned packages at first boot. Its liveness grace
   period is 180 seconds, then normal TCP health checks apply.
3. The verifier now checks `trino-coordinator` and `trino-worker` (the chart's
   real Deployment names), and directly pipes Kubernetes JSON to `jq`.

## Production-equivalent next gate

Obtain a sanctioned non-production Starburst Enterprise target or evaluation
package, Harbor/chart access, SEP and MCP licences, an approved non-human
