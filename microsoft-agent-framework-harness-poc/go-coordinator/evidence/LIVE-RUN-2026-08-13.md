# Go coordinator live run — 2026-08-13

## Scope

Synthetic, reversible HomeLab proof only. The coordinator has no Kubernetes
credentials and did not execute remediation. A separate receipt writer stood
in for an already approved, least-privilege remediation workflow.

## Approved path — PASS

- `maf-go-issue-summariser`, `maf-go-sre-triage`, and
  `maf-go-uk8s-healthcheck` were `Accepted=True, Ready=True`.
- The coordinator received HTTP 200 terminal A2A responses from summary,
  triage, baseline-health, and post-remediation-health stages.
- Baseline health returned `HEALTH: UNHEALTHY`; post-remediation health
  returned `HEALTH: HEALTHY` (both synthetic-only responses).
- The external `remediation-receipt.json` recorded `state: Succeeded`.
- Terminal coordinator record: `status: PASS`, `loop_count: 1`,
  `remediation_started: true`.

## Denied path — PASS

The deny run ended with `status: DENIED` and `remediation_started: false`.
No A2A invocation or remediation receipt was needed for that run.

## Real remediation receipt integration — PASS

The separate Argo Workflow `maf-go-remediation-b4mqc` reached `Succeeded` under
the dedicated `maf-go-remediator` ServiceAccount and changed only
`test-remediation/maf-go-synthetic-health` from `UNHEALTHY` to `HEALTHY`.
The external read-only receipt bridge read that named Workflow terminal state
and wrote `state: Succeeded` for the coordinator. A final coordinator run then
recorded `status: PASS`, `loop_count: 1`, and an HTTP 200 post-remediation A2A
health receipt.

## Bounded retry, fallback, and evaluation — PASS

A second approved coordinator run deliberately set its primary summary agent
to `missing-primary`. It wrote two failed HTTP 404 receipts, then invoked the
explicitly configured equivalent fallback `maf-go-issue-summariser` once. The
fallback recorded HTTP 200 and terminal text. Triage, baseline-health, and
post-remediation-health each recorded one HTTP 200 terminal receipt.

The deterministic receipt evaluator returned `result: PASS` with these six
criteria: coordinator PASS after exactly one remediation loop; named approved
workflow receipt Succeeded; and terminal receipts for summarise, triage,
health-before, and health-after. This proves bounded control flow and receipt
evaluation, not a semantic model-based evaluation.

Each attempt receipt records the stage, chosen agent, HTTP status, attempt,
optional fallback source, error, and timestamp. The historical lab run also
captured bounded response excerpts. The subsequent code hardening makes that
diagnostic opt-in (`RECORD_RESPONSE_EXCERPT=true`) because an agent answer can
contain operational data. This is local JSON receipt observability only; no
OpenTelemetry exporter was deployed in this POC.

## Boundary

This proves Go process -> kagent A2A handoffs, explicit approval state,
bounded retry/fallback, a real least-privilege synthetic Argo remediation,
workflow terminal receipt, deterministic receipt evaluation, and recheck
control flow. It does not prove a real UK8S health inspection, automatic
OpenTelemetry export, or a Microsoft Agent Framework Go workflow
implementation.
