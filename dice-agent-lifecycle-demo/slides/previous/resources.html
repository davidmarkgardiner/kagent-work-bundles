What gets deployed, and why?

KRO uses a ResourceGraphDefinition to reconcile these 14 per-agent resources. Native kagent runs the agent.

Resource kind / countWhich instances?Why deploy it?
Agent1The agent definitionConnects the system prompt, model, skills, and selected MCP tools.
ServiceAccount3Runtime, verifier, callerGives the agent, its test, and its caller separate identities.
NetworkPolicy2Agent and verifier boundariesRestricts which network paths each workload may use.
AgentgatewayPolicy3Verification, card, caller checksValidates JWTs and authorizes the intended identity on each route.
HTTPRoute3AgentCard, verification, invocationSends each request to the correct agent endpoint.
ConfigMap1Golden test configurationFixes the expected agent, endpoints, and verification settings.

The team submitsOne ClassicSecureAgent request.

The platform providesResourceGraphDefinition, Namespace, Gateway, and two listener policies. Reused: GatewayClass, ModelConfig, RemoteMCPServer, and credentials.

Those supporting objects are outside the 14. A ReferenceGrant is needed only for a cross-namespace backend reference; this same-namespace demo does not install one.

How the agent is hardened

Routes choose the destination. Policies decide who may use it. Workload controls constrain execution.

Caller JWTIdentity for this API.
→
HTTPRoute + JWT policyRoute and authorize.
→
Agent ServiceReach the native runtime.
1

Check the caller

Require the expected JWT issuer, audience, expiry, and exact caller identity.

2

Separate identities

Keep runtime, verifier, and caller distinct. Golden has no Kubernetes API Role or RoleBinding.

3

Restrict network paths

Allow approved Gateway ingress and bounded egress. Enforcement needs the receiving cluster's CNI.

4

Restrict the process

Use non-root, no privilege escalation, read-only root, dropped capabilities, and seccomp. Bound temporary storage, CPU, and memory.

5

Limit capabilities

Select approved models and explicit MCP tool names. Backend permissions remain a separate check.

6

Verify before exposure

Create the caller route only after Golden succeeds. A past pass is not continuous revocation.

AgentCard routeLets the verifier discover the agent interface.

Verification routeLets Golden test the agent separately from callers.

Caller routeThe approved invocation endpoint, created after Golden passes.

4 November proof covers model/caller PONG and JWT denials. Network enforcement, MCP access, and telemetry need separate proof. These sheets explain templates, not a new deployment.
