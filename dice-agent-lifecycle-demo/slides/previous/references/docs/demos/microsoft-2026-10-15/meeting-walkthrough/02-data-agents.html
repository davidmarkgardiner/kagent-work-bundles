The data query loop

A specialist turns an operational question into a permitted data query.

QuestionThe SRE or orchestrator asks a specific question with a time and resource scope.
Tool selectionThe data agent chooses a typed MCP operation over approved data views.
Evidence returnedThe adapter returns a bounded result with its scope and available freshness metadata.
Decision supportThe agent combines that evidence with telemetry and explains the proposed next step.

A concrete query contract

The reference PostgreSQL adapter exposes three named read operations.

Discover the data productget_inventory_data_product_details describes supported operations and limits.
Count namespacesget_namespace_count queries the approved inventory view.
Inspect one namespaceget_namespace_summary(namespace_name) returns ownership, workload counts and observed_at.
Interpret the resultThe agent can identify the owner and compare inventory with live cluster evidence.

Limits before model context

The adapter enforces the response budget before returning data.

Data accessApproved views and read-only database permissions.
Default result limits50 rows, 32 KiB per result and 512 characters per cell.
Execution limitA five-second statement timeout by default.
TruncationExplicit metadata tells the agent to narrow the question or use an aggregate.

Evidence in the final answer

A useful answer explains what the data supports and what still needs checking.

ObservationName the source, query scope, timestamp and returned result.
InterpretationExplain how the result changes the working hypothesis.
Missing contextCall out stale inventory, truncation or unavailable telemetry.
ActionRecommend a bounded next step. Route any write through its approved workflow.
