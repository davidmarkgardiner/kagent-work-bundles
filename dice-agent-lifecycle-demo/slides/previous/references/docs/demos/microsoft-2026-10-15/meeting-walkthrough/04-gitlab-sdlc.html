An issue becomes an engineering task

GitLab records the request and each delivery checkpoint.

IssueCapture the problem, scope and acceptance criteria.
PlanA coordinator creates a bounded child task and delegates to a builder.
ImplementationThe builder commits permitted files on a dedicated branch.
Issue updatesWorkflow notes and labels link the child, commit, pipeline and merge request.

Tests and review follow the commit

Every gate refers to the exact merge-request head.

CIThe pipeline must succeed on the committed branch SHA.
TestingThe tester checks the actual pipeline and repository artifacts.
ReviewA separate reviewer posts PASS or CHANGES_REQUESTED tied to the SHA.
AcceptanceThe coordinator accepts only matching CI and review evidence.

Merge and rollout authority

A reviewable change reaches the authorized merge decision.

SDLC rigThe demonstrated endpoint is an accepted draft MR.
Rollback POCA separate native tool pauses for human approval of an exact MR and head.
GitOps rolloutAfter an authorized merge, Flux reconciles the merged revision.
VerificationA matching applied revision and application probes establish the result.
