The fleet connection path

The agent reaches only the clusters and operations its backend permits.

ScopeResolve the approved cluster, environment, namespace and workload.
Agent bindingThe Agent selects named tools from a RemoteMCPServer.
Tool connectionThe MCP backend reaches the selected Kubernetes or AKS endpoint.
EnforcementBackend resource checks and Kubernetes RBAC constrain the actual operation.

Read-only triage

The specialist gathers observations before proposing a change.

Workload healthInspect deployment status and pod conditions.
Failure contextRead bounded logs, events and scheduling reasons.
CorroborationCompare the cluster evidence with metrics and approved inventory.
ReportReturn observations, likely cause, uncertainty and a proposed next step.

A controlled remediation path

Execution authority belongs to the approved change workflow.

ProposalName the exact resource, change, expected outcome and rollback.
DecisionObtain the required human or policy approval for that scope.
ExecutionA narrowly scoped workflow service account or approved GitOps path performs the change.
ReadbackCheck the applied revision, resource health and application behavior, then update the incident.

What the SRE can inspect

The proposed action stays connected to its evidence and authority.

TargetThe cluster and namespace selected for this investigation.
ToolsThe allowed operations and the resource scope enforced by the backend.
Decision recordWho approved the exact proposed change and when.
OutcomeThe verification receipt and the linked issue or incident update.

Speaker notes

This is the platform connection pattern. An allowed tool name does not validate a cluster or namespace argument. Runtime enforcement must validate those arguments and use credentials scoped to the target. AKS-MCP is one bridge in this repository, not blanket permission to every fleet cluster.
