The incident path

Telemetry arrives with enough context for an agent to investigate.

CollectAlloy collects application logs and Kubernetes events.
PrepareVector redacts, normalizes and bounds the evidence.
DeliverKafka carries the evidence to the triage workflow.
InvestigateArgo invokes a read-only specialist. The workflow records the diagnosis in a GitLab issue.

Metric alerts and direct evidence

The source of the signal determines its route.

Metric conditionAlertmanager supplies grouped metric alerts.
Log or eventAlloy and Vector retain the original reason and representative context.
Routing policyA normalized request identifies its source, workload and incident key.
Shared investigationThe selected agent can query additional evidence after dispatch.

Replay and duplicate handling

Reprocessing an event needs a stable incident identity.

CorrelationCarry cluster, environment, namespace, workload and event time.
AdmissionClaim a durable incident key before dispatching work.
Failure handlingRetain failed messages for controlled investigation and replay.
Side effectsMake ticket updates and changes idempotent at their destination.

A scheduling failure example

The ticket already contains the scheduler's reason and the agent's investigation.

SignalA workload fails scheduling because its node selector does not match.
EvidenceThe pipeline retains the redacted FailedScheduling event.
DiagnosisThe read-only agent checks the pod, node and event evidence.
Operator handoffThe GitLab issue includes the likely cause, confidence and proposed next action.
