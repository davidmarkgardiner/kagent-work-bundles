Tools connected to the agents

The selected tool list is only one part of the permission boundary.

Kubernetes / AKS MCPRead resources, events and bounded logs. Scope downstream RBAC and arguments.
Grafana MCPRead datasources, metrics, logs and dashboard context. Return evidence links.
GitLab MCPRead repository context. Scope any branch, MR or comment writes to an approved project.
Data MCPsExpose fixed operations over approved views. Enforce row, byte and time limits.

Isolation across the whole call path

Every boundary constrains a different kind of authority.

GatewayValidate identity and role. Allow only the intended route and tools.
KubernetesPlatform-owned grants, admission, RBAC and NetworkPolicy restrict cross-team access.
MCP and data sourceTyped arguments, bounded output and least-privilege backend grants restrict effects.
Execution runtimegVisor actors isolate execution. Protect snapshot data, credentials and egress too.

Entra identities and gateway policy

Caller identity, agent identity and backend identity have separate jobs.

Caller front doorA user or workload obtains a token for the A2A API and its application role.
Blueprint and agent identityThe blueprint enables token acquisition for a child agent identity.
Gateway authorizationCheck issuer / audience / signature / expiry, then caller claims, roles and tool name.
Downstream accessAn approved backend identity still needs the database, Grafana or Kubernetes grants.
