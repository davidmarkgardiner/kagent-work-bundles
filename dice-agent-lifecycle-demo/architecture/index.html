The agent, tools and model garden behind controlled routes

Entra supplies destination tokens. The API and Gateway authorize their use. Agents and MCPs have separate workload/backend identities and central registry records. GitLab publishes reviewed skills. Evaluations sit beside OTel/LGTM and gate reviewed releases.

Caller-to-agent and agent-to-MCP are separate token paths

A calling workload uses its UAMI; a human uses an approved interactive client. The agent's trusted credential adapter acquires the MCP API token using the selected Agent ID or per-agent identity profile. API validation can sit with Istio or in application code. Destination audiences and permissions still apply.

Evaluate the release, observe the runtime, assess the outcome

Functional, tool, security and model checks bind to the exact release. Existing approval controls promotion. Runtime evaluation uses approved data and permissions beside metadata-first telemetry. Registry records retain the evidence.
